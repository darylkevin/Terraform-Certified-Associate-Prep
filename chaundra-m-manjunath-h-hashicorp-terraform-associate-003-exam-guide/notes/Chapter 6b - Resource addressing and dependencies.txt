Resource addressing: ways to refer to a particular set of resources
Consist of two parts:
- module path
- resource specifications

Module path

`module.module_name[module_index]`
module.<name_of_module>[<optional_module_index>]

Resource specifications

`resource_type.resource_name[instance_index]`
resource_type.<name_of_resource>[<optional_instance_index>]

resource_type: type of resource being provisioned
resource_name: user-defined value for the resource block
instance_index: to refer particular instance if there are multiple instances

e.g. AWS EC2 (compute module) named test_instance with count = 4

`module.compute.aws_instance.test.instance[1]` # Refer to second element
`module.compute.aws_instance.test.instance[3]` # Refer to fourth element

For key-based, use quotes

e.g.

resource "aws_instance" "web" {
    for_each = {
        "dev": "testinstance",
        "prod": "prodinstance"
    }
}

`aws_instance.web["dev"]`
`aws_instance.web["prod"]`

Resource dependencies
- Implicit dependency
- Explicit dependency

Terraform will try its best to infer the dependency if there are multiple resource referenced in other resource block.
In the case it is not able to infer, we need to explicitly specify the dependency
We can use `depends_on` argument to do this

Example of implicit dependency:
You have two resource block, aws_instance and aws_eip
Terraform will create aws_instance first then assign the elastic IP to the instance (inferred)

Use `depends_on = [resource_type.name]` to explicitly states the dependency

Example of explicit dependency:

```
resource "aws_s3_bucket" "appbucket" {}
resource "aws_instance" "test_instance" { 
    ...
    depends_on = [aws_s3_bucket.appbucket]
}
```

In this case terraform will create the bucket first, then create the instance
